# saguri の仕組み

saguri は fzf と同じ考え方のあいまい検索を、Swift で書いたものです。ランチャー [taguri](https://github.com/akameco/taguri) の候補の絞り込みに使います。

## 使い方

```swift
import Saguri

let matcher = Matcher("ghd")          // パターンの前処理は 1 回だけ
if let m = matcher.match("GitHub Desktop") {
    print(m.score, m.positions)        // 点数と、一致した文字の位置
}
```

`Options` で次を切り替えられます。

| 設定 | 既定 | 意味 |
|---|---|---|
| `caseMode` | `.smart` | パターンに大文字があるときだけ大文字小文字を区別する |
| `kanaInsensitive` | `true` | カタカナとひらがなを同じ文字とみなす |
| `algorithm` | `.v2` | `.v2` は動的計画法で最善の一致を探す（fzf の既定）。`.v1` は前から見つけた一致を採点する（速いが、見逃すことがある） |

## v1: 範囲を探してから採点する

fzf の `FuzzyMatchV1` と同じ 2 段階です。

### 1. 範囲を探す（`findRange`）

パターン `ab`、候補 `a_a_b` の例です。

```
前向き:  a _ a _ b      a を見つけ、次に b を探す → 終わりは b の次（5）
         ^       ^
後ろ向き: a _ a _ b      終わりから b, a の順に探し直す → 始まりは 2
             ^   ^
範囲:        a _ b      2..<5
```

前向きだけだと、最初に見つかった `a` から始まるので範囲が長くなります。後ろ向きに探し直すと、終わりに近い `a` が選ばれ、範囲が短くなります。どちらも候補を 1 回なめるだけなので、計算量は O(候補の長さ) です。

### 2. 採点する（`score`）

範囲の中を左から見て、点を足し引きします。値は fzf と同じです。

| 出来事 | 点 |
|---|---|
| 1 文字一致 | +16 |
| すき間の始まり | −3 |
| すき間の続き | −1 |
| 空白のあとで一致 | +10 |
| `/ , : ; \|` のあとで一致 | +9 |
| 記号のあとで一致 | +8 |
| camelCase の大文字、数字の始まり | +7 |
| 連続した一致の途中（最低保証） | +4 |
| パターンの 1 文字目のボーナス | 2 倍 |

連続して一致している間は、塊の先頭で得たボーナスを引き継ぎます。`fooBar` に `bar` なら、`B` の +7 を `a` と `r` も受け取ります。人が「Bar」を狙って打ったことを、塊全体で評価するためです。

手計算の例（`foo bar` に `obr`）:

```
添字  2   3   4   5   6
文字  o   ␣   b   a   r
     +16 −3  +16 −3  +16
              +10        ← 空白のあと
合計 52
```

### v1 の弱点

範囲を 1 つに決めてから採点するので、「もっと点の高い一致の仕方」があっても見逃します。`ab` を `a_b ab` に当てる例です。

```
v1 が選ぶ:   [a]_[b] ab     最初に見つかった範囲 → 20+16 −3 +16+8（_ のあと）= 57
最善:         a_b [a][b]    空白のあとの連続 → 20+16 +10+16 = 62
```

前向きの走査は最初に見つかった `b` で止まるので、後ろの連続した `ab` に気づけません。テストの `v1は最善の一致を見逃すことがある` がこの例です。

## v2: 動的計画法（既定）

v1 の弱点を、fzf の `FuzzyMatchV2` と同じやり方で直したものです（`Sources/Saguri/MatcherV2.swift`）。`Options(algorithm: .v1)` で v1 に戻せます。

### 表の意味

表の i 行 j 列は「パターンの i 文字目までを、候補の j 文字目までで当てたときの最高点」です。行がパターンの文字、列が候補の文字です。1 マスの点は、次の 2 つの大きいほうで決まります。

- **左上から（一致）:** 1 つ前のパターンの文字を j−1 文字目までで当て、j 文字目でこの文字に一致させる。`16 + ボーナス` を足す
- **左から（すき間）:** この文字は j−1 文字目までに当て終えていて、j 文字目はすき間にする。`−3`（続くなら `−1`）を足す

点は 0 より下げません。下がるなら、そこから先で始め直したほうがよいからです。

### `ab` を `a_b ab` に当てる

```
添字          0    1    2    3    4    5
文字          a    _    b    ␣    a    b
ボーナス     10    8    8   10   10    0

a の行       36   33   32   31   36   33     a で 16 + 10×2、すき間で −3, −1…
b の行        -    -   57   54   53   62
```

- **b の行の 2 列目（57）:** a の行の 1 列目（33）から一致で来た点。33 + 16 + 8（`_` のあとの境界）= 57
- **b の行の 5 列目（62）:** a の行の 4 列目（36）から一致で来た点。b は a のすぐ後ろなので連続になり、ボーナスは塊の先頭（a の 10）を引き継ぐ。36 + 16 + 10 = 62
- 最後の行でいちばん高い 62 が答えです。v1 の 57 より高い、後ろの `ab` を選びます

### 位置をさかのぼる

答えのマス（b の行の 5 列目）から、「左上（一致）から来たのか、左（すき間）から来たのか」を見て戻ります。一致から来たマスの列が、一致した位置です。同点なら、連続している側を選びます。

### 速さ

一致しない候補は、先に v1 の前向きの走査（O(候補の長さ)）で落とします。表を作るのは一致する候補だけで、大きさは「パターンの長さ × 一致する範囲の長さ」です。5,000 件の候補（2〜5 語）で、v1 が 11ms、v2 が 12〜20ms でした（`swift test -c release`）。表が 10 万マスを超えるときは v1 に戻します（fzf と同じ）。

### fzf の v2 と同じ癖

fzf と同じ並び順にするため、次の癖もそのまま写しています。

- 1 行目は「パターンの 1 文字目が現れるたびに、そこから始め直した点」です。前の a からすき間を続けたほうが高くても、新しい a の点で上書きします。そのため、点数が「選んだ位置を手で数えた点」より少し低く出ることがあります（テスト `先頭の文字のボーナスが大きい位置を選ぶ`）
- 連続のボーナスは「どこから連続しているか」で決まりますが、表の 1 マスには 1 つの経路しか覚えません。そのため最適は保証されず、まれに v1 より低い点になります。乱数の 959 件の一致で 1 件でした（テスト `v2はv1以上の点で正しい位置を返す`）

### fzf と比べて確かめる

fzf が入っていれば、テスト `fzfと同じ並び順になる` が `fzf -f <パターン> --tiebreak=index --algo=v2` の出力順と比べます。fzf は点数を出しませんが、並び順（点数の高い順、同点は入力の順）は比べられます。記号を含むパターンも含めて、150 回とも一致しています。

fzf と違うのは、アクセントの扱いです。fzf は既定で `é` を `e` とみなしますが、saguri がそろえるのは大文字小文字とカタカナ・ひらがなだけです。

### Swift の書き方で新しく出てきたもの

| Swift | TypeScript / Rust で近いもの |
|---|---|
| `extension Matcher { ... }` | 型に後からメソッドを足す。Rust の `impl Matcher { ... }` を別の場所に書くのと同じ |
| `[Int](repeating: 0, count: n)` | `new Array(n).fill(0)`、`vec![0; n]` |
| `h.replaceSubrange(0..<width, with: h0[f0...lastIdx])` | `splice`、`copy_from_slice`。`a...b` は b を含む範囲、`a..<b` は含まない |
| `max(s1, s2, 0)` | 引数をいくつでも取れる。`Math.max` と同じ |
| `RandomNumberGenerator` に従う型 | 乱数の種を決められる自前の乱数。`randomElement(using:)` に渡せる |
| `&+`、`&*` | あふれても落ちない演算。Rust の `wrapping_add`、`wrapping_mul` |
| `private` がファイルの中だけで見える | TypeScript の `private`（クラスの中）より広く、Rust の `pub(crate)` より狭い。別のファイルの extension から読む値は `private` にしない |

## Swift を読むときの手がかり

| Swift | TypeScript / Rust で近いもの |
|---|---|
| `struct`（値型） | Rust の `Clone` な struct。代入でコピーされる |
| `Match?`（Optional） | `Match \| undefined`、`Option<Match>` |
| `guard 条件 else { return }` | 早期 return |
| `enum Score { static let ... }` | 名前空間だけのモジュール |
| `Character` | 見た目の 1 文字（書記素クラスタ）。絵文字も 1 文字 |
| `String.Index` | 文字列の位置。整数では引けない（UTF-8 が可変長のため） |
| `Sendable` | スレッドをまたいで渡せる印。Rust の `Send` |
| `@Test`, `#expect` | Jest の `test`, `expect`、Rust の `#[test]`, `assert!` |
